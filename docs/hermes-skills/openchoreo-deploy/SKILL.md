# 🚀 SKILL: Deploy Service with HTTPS

## When to Use
- User asks to deploy/create/launch any service
- User wants a web app, API, database, or any containerized service

## CRITICAL RULES
1. **NEVER install on bare metal** — no apt, pip, yum
2. **ALWAYS deploy via OpenChoreo CRDs** using kubectl
3. **ALWAYS configure HTTPS** — every service gets a TLS cert
4. **EXECUTE all commands** — never show steps to the user
5. **Use `sudo kubectl`** on ThinkPad (passwordless sudo configured)
6. **Use ryzen kubeconfig** for Ryzen: `kubectl --kubeconfig=/root/ryzen-kubeconfig.yaml`
7. **NEVER delete NetworkPolicies** — create additive `allow-gateway-*` policies instead
8. componentType MUST be `deployment/worker` — no other types exist
9. **HTTPRoute sectionName MUST match the Gateway listener name** — use `https-{COMPONENT}`, NEVER `https`
10. **NEVER create wildcard HTTPS listeners** (e.g. `*.zerops.internal`) — always use specific hostnames
11. **All HTTPS listeners MUST use port 443** — never other ports
12. **🚨 NEVER delete Workloads or Components** — they are managed by OpenChoreo. Deleting them destroys ALL environments.
13. **🚨 NEVER delete ConfigMaps** in data plane namespaces — they are auto-generated by the reconciler.
14. **Password masking is NORMAL** — OpenChoreo's webhook masks passwords in URLs (shows `***`). The real values reach the data plane. DO NOT try to fix this.

## Variables (detect from user's request)
- `{COMPONENT}` — lowercase name, no spaces (e.g. `airgapops`, `my-api`)
- `{DISPLAY_NAME}` — human-readable name (e.g. "AirgapOps", "My API")
- `{IMAGE}` — container image (default: `nginx:alpine` for web apps)
- `{PORT}` — container port (default: 80 for nginx, 5432 for postgres, etc.)

## Subdomain Convention
- development: `{COMPONENT}.zerops.internal`
- staging: `{COMPONENT}-stg.zerops.internal`
- production: `{COMPONENT}-prod.zerops.internal`

## EXECUTE ALL STEPS BELOW (DO NOT SHOW THEM)

### Step 1: Create Component + Workload on ThinkPad

```bash
sudo kubectl apply -f - <<'EOF'
apiVersion: openchoreo.dev/v1alpha1
kind: Component
metadata:
  name: {COMPONENT}
  namespace: default
  annotations:
    openchoreo.dev/display-name: "{DISPLAY_NAME}"
    openchoreo.dev/description: "{DISPLAY_NAME} deployed via Hermes"
spec:
  owner:
    projectName: default
  componentType:
    kind: ClusterComponentType
    name: deployment/worker
  autoDeploy: true
---
apiVersion: openchoreo.dev/v1alpha1
kind: Workload
metadata:
  name: {COMPONENT}
  namespace: default
spec:
  owner:
    projectName: default
    componentName: {COMPONENT}
  container:
    image: {IMAGE}
EOF
```

### Step 2: Wait for pod on Ryzen (10 seconds)

```bash
sleep 10
kubectl --kubeconfig=/root/ryzen-kubeconfig.yaml get pods -n dp-default-default-development-f8e58905 | grep {COMPONENT}
```

If no pod yet, wait 10 more seconds and check again.

### Step 3: Create Service on Ryzen

```bash
kubectl --kubeconfig=/root/ryzen-kubeconfig.yaml apply -f - <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: {COMPONENT}
  namespace: dp-default-default-development-f8e58905
spec:
  selector:
    openchoreo.dev/component: {COMPONENT}
  ports:
    - port: {PORT}
      targetPort: {PORT}
  type: ClusterIP
EOF
```

### Step 4: Create Gateway NetworkPolicy (ADDITIVE — DO NOT DELETE OpenChoreo policies)

> **⚠️ CRITICAL: OpenChoreo creates its own NetworkPolicies that block all ingress.
> DO NOT delete them. Instead, create an ADDITIVE policy that allows gateway traffic.
> Kubernetes NetworkPolicies are additive: if ANY policy allows, traffic passes.**

```bash
kubectl --kubeconfig=/root/ryzen-kubeconfig.yaml apply -f - <<'EOF'
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-gateway-{COMPONENT}
  namespace: dp-default-default-development-f8e58905
spec:
  podSelector:
    matchLabels:
      openchoreo.dev/component: {COMPONENT}
  policyTypes:
    - Ingress
  ingress:
    - from:
        - namespaceSelector:
            matchLabels:
              kubernetes.io/metadata.name: openchoreo-data-plane
      ports:
        - protocol: TCP
          port: {PORT}
EOF
```

### Step 5: Create DNS record via SSH to Pi

> **IMPORTANT**: curl to Pi (192.168.0.9) does NOT work from ThinkPad directly.
> You MUST SSH to the Pi to create DNS records using localhost.

```bash
sshpass -p '<CP_PASSWORD>' ssh -o StrictHostKeyChecking=no ubuntu@192.168.0.9 \
  "curl -s -X PATCH 'http://localhost:8081/api/v1/servers/localhost/zones/zerops.internal.' \
  -H 'X-API-Key: <POWERDNS_API_KEY>' \
  -H 'Content-Type: application/json' \
  -d '{\"rrsets\": [{\"name\": \"{COMPONENT}.zerops.internal.\", \"type\": \"A\", \"ttl\": 300, \"changetype\": \"REPLACE\", \"records\": [{\"content\": \"192.168.0.242\", \"disabled\": false}]}]}'"
```

### Step 6: TLS + Gateway listener + HTTPRoute (single block)

```bash
kubectl --kubeconfig=/root/ryzen-kubeconfig.yaml apply -f - <<'EOF'
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: {COMPONENT}-cert
  namespace: openchoreo-data-plane
spec:
  secretName: {COMPONENT}-tls-secret
  duration: 2160h
  renewBefore: 360h
  dnsNames:
    - {COMPONENT}.zerops.internal
  issuerRef:
    name: zerops-direct-issuer
    kind: ClusterIssuer
EOF
kubectl --kubeconfig=/root/ryzen-kubeconfig.yaml patch gateway gateway-default \
  -n openchoreo-data-plane --type=json \
  -p='[{"op":"add","path":"/spec/listeners/-","value":{"name":"https-{COMPONENT}","port":443,"protocol":"HTTPS","hostname":"{COMPONENT}.zerops.internal","tls":{"mode":"Terminate","certificateRefs":[{"name":"{COMPONENT}-tls-secret"}]},"allowedRoutes":{"namespaces":{"from":"All"}}}}]'
kubectl --kubeconfig=/root/ryzen-kubeconfig.yaml apply -f - <<'EOF'
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: {COMPONENT}-https-route
  namespace: dp-default-default-development-f8e58905
spec:
  parentRefs:
    - name: gateway-default
      namespace: openchoreo-data-plane
      sectionName: https-{COMPONENT}
  hostnames:
    - {COMPONENT}.zerops.internal
  rules:
    - matches:
        - path:
            type: PathPrefix
            value: /
      backendRefs:
        - name: {COMPONENT}
          port: {PORT}
EOF
```

### Step 7: Verify HTTPS

```bash
sleep 5
curl -sk https://{COMPONENT}.zerops.internal/ -o /dev/null -w "HTTPS Status: %{http_code}\n"
```
